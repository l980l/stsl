# 모디파이어 UI 표기 + 수치 인플레이션 방지

> 리서치 일시: 2026-05-22
> 리서치 방법: 웹검색

## 요약

- **합연산 vs 곱연산은 단어·기호로 구분하는 것이 업계 관습이다.** Path of Exile은 `increased`(합산)와 `more`(곱연산)라는 별도 단어를 쓰고, Diablo 4는 툴팁에 `[+]`(합산 버킷)와 `[x]`(독립 곱연산)라는 기호 아이콘을 붙인다. 같은 수치라도 곱연산이 훨씬 강하기 때문에, 적용 방식을 텍스트만으로 명확히 알리는 것이 플레이어 빌드 의사결정의 핵심이다.
- **`+25%`는 합산, `×1.25`/`최종 ×`는 곱연산**이라는 기호 관습을 일관되게 지켜야 한다. 곱연산 효과를 `+10%`로 표기하면 플레이어가 합산으로 오해해 빌드 계산이 어긋난다. 모든 모디파이어를 `+`로 통일 표기하는 것이 가장 흔한 설계 실패다.
- **곱연산이 폭증해 수치 인플레이션을 일으키지 않게 하려면**: ① 곱연산(글로벌 멀티) 소스 개수를 의도적으로 적게 제한, ② 같은 종류 합산 모디파이어를 하나의 버킷으로 통합, ③ 합산 버킷 자체가 자연스러운 감소 수익을 만든다는 점을 활용, ④ 너무 강한 효과는 곱연산에서 합산 버킷으로 옮기는 리밸런싱이 표준 처방이다.
- **카드 게임/로그라이크**는 키워드 시스템(굵은 글씨 + 툴팁)으로 효과 적용 방식을 압축 전달한다. Slay the Spire의 "Cards containing 'Strike' deal 3 additional damage"처럼 *additional*(합산) / *double*(곱연산) 같은 동사를 명확히 구분해 적는다.

## 상세 내용

### 1. 게임들의 합연산 vs 곱연산 모디파이어 구분 표기

#### Path of Exile — 단어로 구분
PoE는 모디파이어 적용 방식을 별도 단어로 못박는다.
- `increased` / `reduced` → **합연산(additive)**. 같은 스코프의 다른 합산 스탯과 모두 더해진 뒤 베이스 스탯에 한 번 곱해진다.
- `more` / `less` → **곱연산(multiplicative)**. 각 효과가 순차적으로 따로 곱해진다.

같은 수치라면 `more`가 `increased`보다 훨씬 강력하다. 빌드가 장비 수치는 높은데 약하게 느껴진다면, 대개 같은 합산 버킷 안에서만 스택을 쌓고 곱연산 스케일링으로 분기하지 못했기 때문이다.
(출처: http://www.vhpg.com/poe-more-vs-increased/ , https://www.pathofexile.com/forum/view-thread/892570 , https://fextralife.com/hidden-mechanics-most-arpgs-never-explain/ )

#### Diablo 4 — 기호 아이콘으로 구분
D4는 옵션 `Advanced Tooltip Information`을 켜면 툴팁에 적용 방식 아이콘을 표시한다.
- `[+]%` → **합산 버킷(Additive Damage Multiplier)**에 들어가는 값. Close Damage, Distant Damage, Core Skill Damage, Vulnerable Damage, Critical Strike Damage, Overpower Damage 등이 모두 하나의 버킷으로 합산된다.
- `[x]%` → **독립 곱연산(Global Multiplier)**. 보통 조건부(예: 취약 적 타격 시)이며 다른 글로벌 멀티와 곱셈으로 스택된다. 글로벌 멀티가 다른 데미지 증가 스탯보다 데미지 상승폭이 크다.

D4 툴팁의 또 다른 핵심: 합산 버킷용 스탯은 **툴팁 아래쪽(bottom) 수치**를 계산에 써야 한다. 위쪽 수치는 이미 글로벌 멀티의 영향을 받은 값이라 오해를 부르고, 아래쪽 수치가 곱연산 스케일링 적용 전 순수 합산 기여분이다.
(출처: https://www.thegamer.com/diablo-4-how-advanced-tooltips-work/ , https://maxroll.gg/d4/resources/in-depth-damage-guide , https://us.forums.blizzard.com/en/d4/t/this-is-why-your-damage-sucks%E2%80%94a-psa-on-damage-modifiers/58203 )

#### 기호 표기 관습
- `+25%` → 합산 의미. 같은 버킷에 더해진다.
- `×1.25` 또는 `최종 ×` / `[x]` → 곱연산 의미. 별도로 곱해진다.
- **설계 원칙**: 곱연산 효과는 절대 `+10%`로 적지 말고 `×10%` 또는 `x10%`로 적어야 한다. 모든 모디파이어를 결합 방식과 무관하게 `+10%`로 통일 표기하는 것이 가장 흔한 설계 문제다.
(출처: https://www.pathofexile.com/forum/view-thread/892570 , https://www.thegamer.com/diablo-4-how-advanced-tooltips-work/ )

### 2. 툴팁만 보고 "어느 풀에 들어가 어떻게 곱해지는지" 이해시키는 UI 설계 원칙

- **시각적 구분 기호 부여**: D4의 `[+]` / `[x]` 아이콘처럼, 효과의 결합 방식을 한눈에 보이는 기호로 분류한다. 색상·아이콘·접두 단어 셋 중 최소 하나는 일관되게 적용한다.
- **단어 자체에 의미 부여**: PoE의 `increased`/`more` 처럼, 적용 방식이 단어에서 바로 드러나면 별도 학습 없이도 플레이어가 구분한다.
- **버킷 노출**: D4는 합산 스탯들이 모여 하나의 "Additive Multiplier"라는 버킷을 형성한다는 사실 자체를 어드밴스드 툴팁에서 보여준다. 플레이어가 "이 +20%가 어떤 풀에 합쳐지는가"를 인지하게 만든다.
- **계산용 수치를 분리 표기**: 툴팁이 "표시용 값(이미 다른 배수가 반영된 값)"과 "계산용 베이스 값"을 모두 보여줘, 플레이어가 직접 빌드 계산을 할 수 있게 한다(D4의 bottom value).
- **합산 버킷의 감소 수익을 인지시키기**: 합산 버킷이 클수록 추가 `+%`의 상대 효율이 떨어진다는 점을 가이드/툴팁이 명시해, 플레이어가 곱연산 분기로 유도되도록 한다.
(출처: https://maxroll.gg/d4/resources/in-depth-damage-guide , https://www.thegamer.com/diablo-4-how-advanced-tooltips-work/ , http://www.vhpg.com/poe-more-vs-increased/ )

### 3. 수치 인플레이션(곱연산 폭증) 방지 설계 패턴

#### 곱연산 소스를 의도적으로 적게 제한
곱연산(글로벌 멀티)은 각 소스가 서로 곱해지므로 개수가 늘면 데미지가 기하급수적으로 폭증한다. 그래서 D4의 글로벌 멀티 `[x]` 스탯은 수가 적고 대부분 **조건부**(취약 적, 특정 상태 등)로 설계돼, 항상 켜지지 않게 만들어 폭증을 억제한다.
(출처: https://maxroll.gg/d4/resources/in-depth-damage-guide )

#### 같은 종류 모디파이어를 하나의 합산 버킷으로 통합
같은 계열 모디파이어(예: 모든 "데미지 증가" 류)를 별도 곱연산으로 두지 않고 **하나의 합산 버킷에 모아 더한다**. 모디파이어 배열을 연산자 종류로 정렬해 "덧셈은 모두 먼저, 곱셈은 그 뒤"처럼 처리 순서를 고정하면 곱연산 스택 폭발을 막을 수 있다. 핵심 아이디어는 모디파이어를 분리된 합산 버킷으로 통합한 뒤 곱연산 스케일링에 적용해, 여러 `%` 증가가 기하급수적으로 곱해지는 "스태킹 폭발"을 방지하는 것이다.
(출처: https://howtomakeanrpg.com/r/a/how-to-make-an-rpg-stats.html , https://refreshertowelgames.wordpress.com/2024/02/17/how-to-comfortably-deal-with-modifiable-stats/ )

#### 합산 버킷의 구조적 감소 수익(diminishing returns)
합산 버킷은 그 자체로 자연스러운 감소 수익을 만든다. 베이스 100%에서:
- `+60%` 추가 → 160% (상대 이득 60%)
- 다시 `+60%` → 220% (상대 이득 37.5%)
- 버킷이 2000%일 때 `+60%` → 2060% (상대 이득 3%)

같은 절대값을 더해도 버킷이 클수록 상대 효율이 떨어진다. 이 구조 덕분에 합산 버킷에 스탯을 몰아넣어도 데미지가 무한히 폭증하지 않는다.
(출처: https://maxroll.gg/d4/resources/in-depth-damage-guide )

#### 명시적 감소 수익 공식
별도 공식으로 감소 수익을 강제하기도 한다. 대표 패턴:
- **거듭제곱/제곱근형** `x^y` (0 < y < 1): 입력이 커질수록 산출 증가폭이 줄어든다.
- **음의 지수** (y < 0).
- **지수 감쇠(exponential decay)**: 1에서 0으로 수렴, 부호 반전·곱으로 스케일 조정이 쉬워 가장 선호되는 형태.

설계 원칙: 어떤 공식이든 "추가 투자에는 (사소하더라도) 항상 보상을 주고, 더 투자했다고 패널티를 주지는 않는다"를 지켜야 한다.
(출처: https://blog.nerdbucket.com/diminishing-returns-in-game-design/article , https://blog.nerdbucket.com/diminishing-returns-in-game-design-roots-and-negative-exponents/article , https://blog.nerdbucket.com/diminishing-returns-in-game-design-exponential-decay-and-convergent-series/article )

#### 곱연산 → 합산 버킷으로 옮기는 리밸런싱
어떤 효과가 곱연산이라 지나치게 강하면, 그 효과를 곱연산에서 빼서 합산 버킷으로 옮기는 것이 표준 처방이다. 합산 버킷의 감소 수익이 자동으로 그 효과의 한계 효율을 깎아주기 때문에, 수치를 직접 너프하지 않고도 폭증을 잡을 수 있다.
(출처: https://maxroll.gg/d4/resources/in-depth-damage-guide , https://refreshertowelgames.wordpress.com/2024/02/17/how-to-comfortably-deal-with-modifiable-stats/ )

### 4. 카드 게임/로그라이크의 효과 텍스트 전달 사례

#### Slay the Spire — 키워드 시스템
키워드는 게임 메커니즘상 정의된 의미를 가진 단어로, 카드·유물에 **굵은 글씨**로 표기되며 호버 시 툴팁(코드 + 아이콘 + 설명 텍스트 + 관련 링크)을 띄운다. 키워드 시스템 덕분에 카드 텍스트를 짧게 유지하면서도 정확한 규칙을 전달할 수 있다.
- 곱연산이 거의 없는 설계: STS는 데미지 증가 대부분을 합산형(예: Strength로 타격당 데미지 +N)으로 처리해 수치 폭증을 구조적으로 억제한다.
- **동사로 결합 방식 구분**: `additional`(합산) vs `double`(곱연산)을 텍스트에서 명확히 구분. 예) Strike Dummy 유물 — "Cards containing 'Strike' deal 3 additional damage"(합산, 타격당 고정 +3).
- 카드 텍스트 일관성 사례: 커뮤니티에서 Caltrops 카드가 Thorns 키워드를 안 쓰고 전체 설명을 풀어 적어 혼란을 준다는 지적 → "Gain Thorns" 키워드 + 툴팁으로 통일하는 편이 덜 헷갈린다는 제안.
- STS는 단일 플레이어 로그라이크라 카드 간 밸런스가 PvP 카드게임보다 자유롭고, 순수 밸런스보다 재미를 위해 조정할 수 있다.
(출처: https://slaythespire.wiki.gg/wiki/Keywords , https://slay-the-spire.fandom.com/wiki/Keywords , https://steamcommunity.com/app/646570/discussions/2/1761356057426342101 , https://www.oreateai.com/blog/the-humble-strike-dummy-a-surprising-boost-in-slay-the-spire/3643efe6b5ef99defcf7cfcf7f4e7967 , https://www.gamedeveloper.com/design/how-i-slay-the-spire-i-s-devs-use-data-to-balance-their-roguelike-deck-builder )

#### Magic: The Gathering — 대체 효과로서의 곱연산
MtG의 데미지 더블러(Furnace of Rath, Fiery Emancipation, City on Fire 등)는 대부분 **대체 효과(replacement effect)**다. "deal damage"를 "deal 2x damage" 또는 "3배"로 치환한다.
- 곱연산이 명시적으로 곱셈으로 동작: 더블러 2장이 동시에 깔리면 데미지는 4배가 된다.
- 여러 대체 효과가 같은 대상에 적용될 때는 영향을 받는 플레이어/오브젝트의 컨트롤러가 적용 순서를 정한다 — 곱연산이라 순서가 결과값에는 영향 없지만, 규칙상 명시적으로 처리 순서를 정의한다.
- 시사점: 곱연산 효과는 카드 텍스트에서 `double`/`triple` 같은 명확한 곱셈 동사로 적어, `+` 합산 표현과 절대 섞이지 않게 한다.
(출처: https://articles.starcitygames.com/magic-the-gathering/double-and-triple-magic-the-gatherings-iconic-damage-multipliers/ , https://www.mtgsalvation.com/forums/magic-fundamentals/magic-rulings/magic-rulings-archives/281258-double-double-damage )

#### 본 프로젝트(stsl)에 적용할 시사점
- 카드/유물 효과 텍스트에서 **합산은 "추가 데미지 +N" / "데미지 +N%"**, **곱연산은 "데미지 ×N" / "최종 데미지 N배"**로 동사·기호를 분리해 표기한다.
- 곱연산 소스(시너지 최종 배수 등)는 개수를 의도적으로 적게 두고, 같은 계열 버프는 하나의 합산 버킷에 모은다.
- 강한 곱연산이 시너지 폭증을 일으키면, 곱연산에서 합산 버킷으로 옮겨 감소 수익으로 자연 너프한다.
