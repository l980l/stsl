# 챕터 자동 플레이와 성능 측정

## 목적과 범위

실제 게임 씬에서 맵 선택 → 전투 → 보상 → 휴식/상점/이벤트 → 영입/강화 → 보스를 자동 진행하는 내부 테스트다. 챕터 1과 2는 각각 새 런으로 시작하며, 각 3막·15층이므로 둘을 완주하면 경로상 90개 방을 방문한다. 이는 모든 분기·영웅·카드·적을 검사한다는 뜻이 아니다.

봇의 판단 능력과 게임 난이도를 구별한다. HP·피해·보상을 조작하거나 승리를 강제로 처리하지 않는다. 패배는 관측된 정책의 패배이며 게임이 클리어 불가능하다는 증거가 아니다. 시간/행동 제한에 도달한 런은 성공이 아닌 제한 종료다.

## 실행

프로젝트 루트에서 실행한다. 실행마다 별도 임시 프로젝트와 `STSL-campaign-bot-*` user 디렉터리를 만들며 기존 플레이어 저장을 사용하지 않는다. 기본 보고서·프레임 기록·엔진 로그는 Git 제외 경로 `log/campaign-bot/STSL-campaign-bot-고유이름/`에 남겨 `/tmp` 자동 정리와 구별한다. 임시 프로젝트와 보고서는 실행기가 삭제하지 않는다. 엔진 경로가 다르면 `GODOT_BIN` 환경 변수를 설정한다.

```sh
# 실제 화면: 정상 배속 측정.
bash tools/run_campaign_bot.sh --chapter=both --hero=cleopatra --seed=42

# 기능 진행 확인용: headless 결과를 GPU 성능으로 해석하지 않는다.
bash tools/run_campaign_bot.sh --headless --chapter=both --hero=cleopatra --seed=42 --speed=8 --max-seconds=900
```

현재 봇 옵션과 정책은 [campaign_bot.gd](../tools/campaign_bot.gd)를 정본으로 한다. 렌더링·배속·정책·시드가 다른 결과를 같은 조건의 비교로 취급하지 않는다. 초기 시작 영웅 선택은 테스트 설정이며 영입은 게임의 실제 기회를 사용한다.

기본값은 챕터 `both`, 클레오파트라, 시드 `42`, 정상 배속, 제한 3,600초다. `--hero`는 격리 저장에서 기본 해금된 영웅만 허용한다. 결과 `clear`/종료 코드 0은 요청한 모든 챕터의 실제 승리를 뜻한다. 패배·시간/행동 제한은 코드 1, 엔진 오류·보고서 누락은 실행기 코드 2다. 승리 보고서에도 엔진 오류가 있으면 성공 종료로 취급하지 않는다.

경로 정책은 연결된 다음 방을 내다보고 첫 정예 영입 기회·휴식·이벤트를 고려한다. 상점에서는 실제 가격으로 회복을 구매한다. 전투는 카드 효과·에너지·적의 현재 의도·카운터 기회를 보고 선택하며 스턴 자동 건너뛰기를 존중한다. 보상은 생성된 후보에서 선택한다. 학습 모델이나 완벽한 전략은 아니므로 어느 시드에서나 승리를 보장하지 않는다.

## 평가 프로필

테스트는 기본 무음이다. 실행기가 시작부터 `--audio-driver Dummy`를 사용하며 봇은 격리된 저장의 마스터 볼륨을 0으로 설정하고 Master 버스를 음소거한다. 실제 사용자 음량 설정은 변경하지 않는다. VFX 전용 검사를 직접 실행할 때도 `--audio-driver Dummy`를 붙인다. 무음 드라이버의 결과로 실제 오디오 출력 장치의 성능까지 검증했다고 해석하지 않는다.

게임 루프는 영웅별 덱·에너지·ATB 전투와 보상 선택, 맵 경로 관리다. 목표는 자동 정책이 실제 진행 흐름을 수행하고 느린 상황의 단서를 남기는지 확인하는 것이다. 평균 승률이나 재미 점수를 목표로 삼지 않는다.

| 가설 | 측정 계약 | 판정과 후속 |
|---|---|---|
| 챕터 진행 흐름을 자동 수행할 수 있다 | 한 시드·챕터 런, 실제 게임 승리 플래그와 도달 막/층·행동 기록 | 실제 최종 보스 승리만 clear. defeat/stall/cap은 별도 진단 |
| 프레임 급증과 행동 문맥을 찾을 수 있다 | 한 프레임의 wall-clock 간격(ms), 전체 측정 프레임 수, >33.333ms·>50ms 개수/전체 프레임 수, p50/p95/p99/max | 정상 배속·실제 렌더링에서 관측된 급증을 동일 조건의 짧은 재현 시나리오로 좁힌다 |
| 측정이 플레이어 진행을 훼손하지 않는다 | 모든 자동 로드/저장의 user 디렉터리와 프로젝트 설정 | 격리 이름 검사 실패 시 봇 진행을 거부 |

`report.json`과 `.frames.jsonl`에 진행 및 느린 프레임/최근 행동을 저장한다. 소스 커밋·dirty 상태·규칙 소스 지문은 실행기가 환경 변수로 전달한다. 작업 트리의 수정은 보존하며 Git 커밋·푸시는 실행하지 않는다.

지문 범위는 `autoload/resources/scenes/tools`의 `.gd/.tscn/.csv`다. 아트·음원·셰이더 등 다른 자산이 바뀐 비교에서는 지문만으로 동일 빌드라고 판단하지 않는다. 엔진 버전·OS·렌더러와 설정도 보고서/엔진 로그를 함께 확인한다.

## 해석의 한계

- 프레임 간격은 GPU 실행 시간이 아니다. VSync·OS 스케줄링·초기 로딩·전환·봇 판단/기록 오버헤드를 포함한다. `process_ms`와 draw calls도 원인 확정값이 아니다.
- headless와 가속 실행은 규칙/진행 검사에 쓰고 정상 렌더링 FPS의 증거로 쓰지 않는다.
- 맵은 명시적 시드로 생성한다. 전역 RNG를 공유하는 연출·음원과 전투가 있어 시드만으로 다른 렌더러/배속의 완전 동일 궤적을 보장하지 않는다. 실제 경로/행동 기록도 함께 비교한다.
- 같은 시드·정책의 반복은 독립적인 플레이어 표본이 아니다. 완주는 정책 커버리지이며 사람의 조작성·재미·숙련도 증거가 아니다.
- 긴 완주는 정기 검사로, 짧은 전투/동작 검사는 일상 회귀 검사로 사용한다. 향후 특정 느린 상황이 확인되면 별도 짧은 재현 테스트를 추가한다.

## 자동 검사로 발견한 실제 오류

- 전투 초기화가 영웅별 보유 더미를 버리고 초기 덱에서 재구성해 보상이 사라졌다. 현재 덱을 한 번 스냅샷해 재분배하며, 영입 대기 카드도 전체 덱·저장에 포함한다. 보상 유지·영입·직렬화·제거·소멸 카드 복귀를 별도 회귀 검사로 확인한다.
- 영웅의 침묵 지속 시간이 감소하지 않았다. 해당 영웅 턴 종료 처리에서 다른 일시 상태와 같이 감소하도록 수정했다.
- 캐릭터 씬 없는 소환 적의 폴백이 `Control`이라 `Node2D`를 전제로 하는 전투 연출에서 실패했다. 자식 사각형을 가진 `Node2D`로 수정했다.
- 사기/발톱/소환 연출에서 0 또는 음수 크기의 도형·선이 발생했다. 경계 크기를 검사하고 보간을 제한했다.
- 이순신의 N번째 공격 보너스 표시가 번역 문자열의 인자 두 개 중 하나만 전달했다. 주기·피해 모두 전달한다.
- 독에 마지막 영웅이 사망한 경로에서 패배 검사가 누락됐으며, 턴 시작 독에 죽은 영웅에게 입력을 열 수 있었다. 패배 처리와 생존 큐로의 진행을 별도로 회귀 검사했다.
- 파티클이 씬과 함께 삭제돼도 타이머가 로컬 노드 캡처를 호출했다. 파티클 노드 수명에 묶인 종료 콜백으로 변경했다.

120초 동안 게임 행동이 없으면 정체로 종료하고 마지막 씬·액터·입력/카드 대기 상태를 기록한다. 이는 완주 성공이 아니다.

새 전용 검사는 `tests/test_campaign_deck.gd`, `test_campaign_status.gd`, `test_campaign_frame_probe.gd`, `test_campaign_vfx.gd`, `test_campaign_policy.gd`다. 실행기가 출력한 **새 격리 프로젝트 경로**에 `Godot --path 경로 -s res://tests/파일.gd`로 실행한다. VFX 도형 검사는 `--headless` 없이 실제 렌더링으로 실행하며, 성공 출력뿐 아니라 엔진 로그 오류·경고도 확인한다.

전투 정책은 에너지 예산 내 카드 점수 합을 최대화하는 조합을 선택하고 매 사용 후 재평가한다. 현재 씬·액터·턴 시작 신호가 모두 일치할 때만 입력하므로 이전 전투의 입력 가능 상태를 재사용하지 않는다. 불교 적의 사망 반사 피해에 대비해 생존 가능한 HP+방어도를 확보하기 전에는 공격·독·토큰·반격을 보류한다. 이 전략도 모든 시드의 승리를 보장하지 않는다.

## 검증 기록 — 2026-10-10

최신 정상 화면·1배속 완주 성능과 카드 갱신 진단은 [2026-10-11 성능 보고서](performance-profile-2026-10-11.md)를 참조한다. 렌더러 실행 여부와 실제 OS 화면 표시 여부는 구분하며, 프레임 프로브는 씬·창 상태별 분모도 기록한다.

- 전체 기존 회귀 검사: **1,877 통과, 실패 0**. 봇 전용 덱·상태/독 사망·프레임·정책 검사도 통과했다. VFX 검사는 Apple M2 / Metal 실제 렌더링에서 통과했으며 해당 검사 로그에 엔진 오류·경고가 없었다.
- `STSL-campaign-bot-aIcHxG`: 클레오파트라·시드 42·headless·8배속, 90개 방을 진행했으나 결과는 **패배**다. 챕터 1은 클리어했고 챕터 2 최종 보스를 죽였지만 사망 반사에 전멸했다. 소유자 없는 입력은 0회였다. 이 결과를 두 챕터 완주로 취급하지 않는다.
- `STSL-campaign-bot-7YvRFl`: 반사 대비 정책을 개선한 뒤 **챕터 2 실제 클리어**, 45개 방·전투 22회·169.2초, 종료 코드 0. 설정은 클레오파트라·시드 42·headless·8배속이다. 엔진 오류는 없고 미제작 BGM 경고는 남아 있다.
- `STSL-campaign-bot-bKWtiu`: 같은 전투 정책으로 **챕터 1→2 연속 실제 클리어**, 90개 방·전투 23+22회·373.0초. 두 런의 실제 승리 상태, 소유자 없는 입력 0회, 엔진 오류 없음도 확인했다. 설정은 클레오파트라·시드 42·headless·8배속이다. 위 실행 시간은 가속 기능 검사의 시간이지 일반 플레이 시간이나 실제 렌더링 성능이 아니다.
- 연속 검사의 게임 결과는 clear였지만 실행 중 실행기 파일을 수정해 Bash가 오래된 파일 위치에서 읽기를 재개하면서 래퍼는 코드 2로 종료했다. 실행기 전체를 시작 전에 파싱하는 함수로 묶었으며 최종 실행기는 별도 짧은 제한 종료 검사로 재검증했다. 이 실행의 래퍼 종료를 코드 0으로 기재하지 않는다.
- 사용자 요청으로 무음 실행을 추가한 뒤 실제 렌더링 스모크에서 격리 저장의 `master: 0.0`과 보고서의 `master_muted: true`를 확인했다. 3초 제한 종료는 의도된 검사이며 완주가 아니다.

원본은 프로젝트의 `log/campaign-bot/실행이름/` 아래 JSON·JSONL·엔진 로그다. 향후 비교 시 성공만 골라 집계하지 말고 패배와 제한 종료도 보존한다. 기본 재현 설정은 `--hero=cleopatra --seed=42`이며 다른 영웅·시드의 성공을 뜻하지 않는다.
