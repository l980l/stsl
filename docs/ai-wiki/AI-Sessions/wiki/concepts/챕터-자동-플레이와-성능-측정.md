# 챕터 자동 플레이와 성능 측정

## Summary

사용자가 챕터 1·2를 자동 진행하는 봇을 만들고 이후 테스트 기반으로 사용하도록 요청했다. 실제 씬·전투 규칙을 사용하는 내부 봇과 별도 저장 실행기, 프레임 간격/행동 기록 기능을 구현했다. 완주·패배·제한 종료를 구별하고 HP 조작이나 강제 승리를 사용하지 않는다. 완주 검증의 최신 결과는 아래 프로젝트 문서가 정본이다.

## Context

2026-10-12 사용자가 성능 프로파일링 중단과 콘텐츠 개발 전환을 요청했다. 아래 측정은 과거 기록이며 다음 작업으로 자동 재개하지 않는다. 카드 기능 보완에는 무음·격리된 headless 회귀 검사만 사용한다. [[카드-구성-개편안-검토상태]]

각 챕터는 3막·막당 15층이다. 둘의 한 경로 완주는 총 90개 방이며 모든 카드·영웅·적·분기를 커버하지 않는다. 긴 완주는 정기 진행 회귀 검사로, 짧은 전투 재현은 일상 검사로 사용한다. 새 카드 구성은 [[카드-구성-개편안-검토상태]]를 참조한다.

## Details

- `bash tools/run_campaign_bot.sh`로 새 임시 프로젝트·`STSL-campaign-bot-*` user 디렉터리를 만든다. 기존 사용자 저장을 봇으로 진행하지 않는다.
- JSON 보고서와 느린 프레임/최근 행동 JSONL을 로컬에 남긴다. 시드·챕터·배속·소스 지문과 dirty 상태를 결과와 함께 비교한다.
- 정상 렌더링·정상 배속만 실제 프레임 성능 조사에 사용한다. headless/가속 결과는 진행 검사이며 GPU 실행 시간이나 사람의 재미 증거가 아니다.
- 사용자 요청으로 테스트 게임은 무음으로 실행한다. 실행기의 Dummy 오디오 드라이버로 시작 순간부터 출력을 차단하고, 격리 테스트 저장의 마스터 볼륨을 0으로 설정한다. 실제 플레이어 음량 설정은 유지한다. 수동 VFX 검사도 `--audio-driver Dummy`로 실행한다.
- 시드 맵은 재현 가능하지만 연출과 전투가 전역 RNG를 공유한다. 서로 다른 배속/렌더러의 완전 동일 궤적은 보장하지 않는다.
- 자동화의 비동기 씬 전환에는 투명도뿐 아니라 입력 해제와 씬별 단일 선택 가드가 필요하다. 전환 도중 새 전환을 실행하면 이전 fade가 새 tween을 죽여 교착될 수 있다.
- 오래된 `/tmp` 프로젝트를 재사용하면 복사된 `project.godot`만 OS 정리로 사라지고 심볼릭 링크가 남을 수 있다. 그러면 autoload 없는 잘못된 환경의 오류를 게임 오류로 오인하게 된다. 실행기는 매번 새 프로젝트를 생성한다.
- 첫 가속 정책의 1막 10층 패배는 관측된 봇 정책의 패배이며 게임의 클리어 불가능 증거가 아니다. 완주를 가장하기 위한 수치 변경은 하지 않는다.
- 2026-10-10 초기 검사에서는 챕터 1 최종 승리 후 챕터 2 최종 보스에서 패배했다. 반사 대비 정책 개선 후 단일 챕터 2 클리어를 확인했고, `STSL-campaign-bot-bKWtiu`에서는 챕터 1→2 연속 실제 클리어·90개 방·전투 45회·373초를 확인했다. 클레오파트라·시드 42·headless·8배속의 정책 검증이며 모든 시드의 승리나 정상 렌더링 성능을 뜻하지 않는다. 게임 결과와 래퍼 종료 상태를 구별하는 검증 정본·원본 위치는 프로젝트 문서를 참조한다.
- 새 전투의 액터가 정해지기 전에 이전 전투의 입력 가능 상태로 턴을 끝내는 봇 레이스를 발견했다. 씬 ID·액터 ID·현재 턴 시작 신호 일치 조건과 선택 카드별 완료 신호를 검사한다. 이 오류가 섞인 패배를 게임 밸런스 문제로 해석하지 않는다.
- 런이 발견한 실제 오류: 다음 전투 초기화에서 보상 소실·영입 대기 카드 저장 누락, 침묵 지속 시간 미감소, 씬 없는 적의 잘못된 연출 노드 타입, 파워 설명의 포맷 인자 누락, 연출의 퇴화 도형, 삭제된 파티클을 캡처한 타이머. 수정과 전용 회귀 검사를 추가했다.
- 봇 정책은 정상 영입·휴식·상점 회복·보상 선택을 사용한다. 이미 활성화된 파워의 무의미한 재사용을 피하고, 차지 취소뿐 아니라 일반 공격에 대한 카운터도 고려한다. 기본 해금 영웅만 시작 영웅으로 허용한다.
- 전투 씬/관리자 핸들러를 구동하는 테스트이며 마우스로 모든 버튼을 누르는 UI 사용성 검사가 아니다. 미제작 음원 경고도 실제 엔진 로그에 보존한다.
- 저장 필터 1·2·3·4를 충족하는 테스트 운영·재현 위험만 기록했다. Git은 manual이며 커밋·푸시는 하지 않는다.

## 정상 렌더링 기준 갱신 — 2026-10-11

- 실제 화면 표시를 OS 캡처로 확인한 `o7Zinb`에서 정상 1배속 챕터1→2를 완주했다. 90방·45전투·29분34초, 실행기 코드0. 전체 p50 16.678ms, p99 27.445ms, 최대603.566ms. 전투/씬 경계에 긴 프레임이 집중된다. 수치·분모·원본·병목 후보는 아래 성능 보고서가 정본이다.
- 프레임 프로브에 씬 경계·포커스/표시 상태별 분모를 추가했다. 창의 `visible`과 Metal 실행만으로 OS 화면 표시를 증명하지 못한다. 초기 OS 캡처와 focus 기록을 함께 사용한다.
- 이전 `3dBzUZ`·`LvZ1n5`/짧은 렌더링 스모크의 화면 표시 검증이 불충분했다. 특히 LvZ1n5는 복원 전 off-screen이었고 취소했다. 과거 결과를 삭제하지 않고 실제 화면 FPS 기준에서 제외한다.
- 카드 5장 공통 refresh 경로의 별도 측정은 p50 7.589ms, 최대11.604ms였다. 장식 재생성이 최적화 후보이지만 수백 ms 전투 정지의 단독 원인이라는 증거는 아니다. Metal GPU profiler의 0.0ms 출력은 유효한 GPU 계측이 아니며 병목 판단을 보류한다.
- 이번 변경은 계측·진단만이며 게임 최적화는 미적용이다. 테스트는 무음·격리 저장으로 실행했다. 최신 프레임 프로브·봇 정책 검사 통과, 미제작 음원 경고는 남아 있다. 필터1·2·4로 보존, Git manual·커밋/푸시 없음.

## 카드/손패 최적화 — 2026-10-11

- 사용자 요청으로 카드 장식 재생성을 제거하고 같은 손패 노드를 재사용했다. 카드 디자인 변경은 강제 교체를 유지한다. 측정/회귀/씬 전환 변경 상세는 아래 성능 보고서 정본에 기록한다.
- 동일 warm 카드5장 벤치 중앙값7.589→0.158ms(97.9% 감소), 카드/손패42검사·기존 전체 회귀 묶음 통과. 전체 캠페인의 FPS 개선율이나 최악 끊김 해소 증거는 아니다.
- 가속 추가 경로 패배와 정상렌더링75초 제한 종료도 원본에 보존했다. 대부분 unfocused인 짧은 런을 focused 완주와 성능 비교하지 않는다. 조기 종료 ObjectDB 경고는 미해결이며 카드 전용 검사 로그는 오류/경고가 없다.
- 저장 필터1·2·4 적용, Git manual로 로컬 기록만 유지했다. raw/스키마/사용자 저장 변경·커밋·푸시 없음.
- 씬 threaded prefetch는 동기 방식 대조 검사에 없는 종료 RefCounted 경고가 발생해 철회했다. 전환 실패 반환값·실패 신호와 기존 씬 입력 복구만 유지한다. 미확인 최적화를 성능 해결로 기록하지 않는다.

## 씬/일러스트 최적화 — 2026-10-11 후속

- main `1710ca6` 기준 새 `perf/scene-stutters`에서 캐릭터 아트24개 FIFO·종료 해제, startup 전투 PackedScene 사전 준비, 하트 native polygon 검사를 적용했다. 씬 로드는 스레드 없이 시작 화면으로 이동하며 약466ms startup 비용은 남는다.
- 렌더링 CPU 벤치5회 중앙값: 영웅 반복 생성85.336→0.749ms, 같은 적 아트 warm21.305→0.036ms, 하트 cold14.103→7.300ms. 첫 아트 로드는 개선되지 않는다. 개수 제한 캐시는 메모리 사용 증가를 동반한다.
- 최종 단독 정상1배속45초 `VBqULF`: 첫 전투 교체499.199→4.720ms, 첫 ready148.920→146.518ms로 거의 동일; 두 번째 ready263.508→159.268ms는 구성/부하 차이 있는 단일 관측으로 일반 개선율이 아니다. 제한 `stall`·종료1을 완주로 기록하지 않는다. 엔진 오류/경고 없음.
- 하트4096마스크/전체픽셀2검사와 아트캐시17검사 통과. startup cache/전환 실패 복구 PASS(의도한 없는 파일 오류3개). GPU·새 아트·다른 씬 cold load와 전체 focused 완주 FPS는 후속이다.
- 최종 전체 회귀1,886통과·실패0·엔진 오류/경고 없음. 일부 suite의 RNG로 실행별 검사 수가 달라지므로 이전 수와 단순 차감을 하지 않는다.
- 초기 벤치 cleanup 오류와 중간 런 테스트 프로세스 겹침을 구별하여 정본에 남겼다. 사용자 저장·음량은 무음 격리 테스트로 보존했다. 저장 필터1·2·4, Git manual·커밋/푸시 없음.

## 선택적 그림 준비와 GPU 확인 경계 — 2026-10-11

- 사용자 승인으로 전투가 확정된 뒤 필요한 팀/적/해당 보스phase 그림만 검은 전환 화면에서 한 장씩 준비한다. 중복·없는 파일·fallback-only 적 제외, 캐시된 그림은 skip. 전체 챕터 선로딩·새 스레드·배경 RNG 변경은 없다. 총 로드 비용은 남으며 로딩 화면에서 개별 로드 중 잠시 멈출 수 있다.
- 격리 무음 `lgAJWG` 첫 준비2장153.282ms, 전투ready146.518→33.984ms(동기 구간 관측). 캐시/선택/준비29검사, 최종 전체1896검사·실패0, 전환복구 PASS. 원본과 한계는 [후속 보고서](../../../../performance-scene-stutters-2026-10-11.md)가 정본이다.
- **GPU 병목은 확인되지 않았다.** 과거 "GPU 쪽 끊김이 남는다"는 대화 표현은 원인 확정처럼 들릴 수 있어 정정한다. GPU API는0값만 반환해 unavailable로 남겼고 xctrace도 현 환경에서 찾을 수 없었다. 유효한 GPU 시간 없이 GPU 문제라고 기록하지 않는다.
- 분리된 실제 FireBlastGPU ABBA 정본 `vfx-abba-final.json`: phase별181 focused 표본/coverage100%, 프레임p50 모두약16.65ms·최대27.413ms 이하. helper 텍스처 준비 후 첫 이펙트의 파이프라인4회·최대28.514ms. 이 조건에서 수백ms 정지는 재현되지 않았다. 전체 전투/다른 효과를 대표하거나 GPU 문제 부재를 증명하지 않는다. 파티클 품질/개수 변경 없음.
- 진단 도구는 raw frame·render CPU/GPU·draw/object·pipeline을 기록하고 focus95% 미달·headless·비격리/유음 실행을 거절한다. 중간 포커스 실패 보고서는 보존하고 성능 비교에서 제외한다. 측정 도구만 자신의 창을 앞으로 가져온다.
- 다음은 특정 끊김 조합의 재현 또는 유효한 GPU 캡처 환경 확보다. 저장 필터1·2·3·4, 로컬 기록만·Git manual·커밋/푸시 없음. [[STSL-프로젝트-작업-기준]]
