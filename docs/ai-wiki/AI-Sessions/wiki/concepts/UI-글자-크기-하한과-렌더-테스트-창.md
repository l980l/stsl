# UI 글자 크기 하한과 렌더 테스트 창

## Summary

2026-10-26 사용자가 일부 글자 UI의 가시성이 떨어진다고 해서 글자 크기 하한을 토큰으로 만들었다. `SacredTheme.FS_SMALL = 14`, `SacredTheme.FS_TEXT = 16`이고 1920×1080 설계 기준이다. 렌더링 테스트 창이 개발자 화면을 가리고 마우스를 가져가는 문제도 같이 고쳤다.

## 원리

- `canvas_items` 스트레치라 1280×720 창에서는 모든 글자가 2/3로 줄어든다. 기존 9~13px 글자는 실제로 6~9px가 됐다.
- 일반 글자·버튼·설명은 `FS_TEXT`(16)를 쓴다. 모노·대문자 라벨이나 아이콘 위 숫자처럼 자리가 좁은 글자는 `FS_SMALL`(14)을 쓴다.
- `LabelUtils.fit_text`의 최소값도 `FS_SMALL` 이상이다. 도감의 `_fs()`도 `FS_SMALL` 아래로 내려가지 않는다.
- 장식 글리프(✦·▼)는 예외다. 해당 줄에 `# 장식 글리프` 주석을 붙인다.
- 카드 앞면은 예외다(`scenes/card`). 노드 전체가 확대·축소되고 호버 확대로 읽기 때문이다. 10/26에 따로 키웠다. 설명은 10→14px(최소 9), 제목은 13→15px다. 줄바꿈 라벨은 글이 길면 스스로 키가 커지므로, `fit_text`에 칸 높이 70을 `target_h`로 넘겨야 실제로 줄어든다. 넘기지 않으면 긴 설명이 카드 밖으로 넘친다. `tests/test_card_text_fit.gd`가 전체 432장(기본+강화)을 13개 언어로 넘침 검사한다. 가장 긴 설명은 ko 89자에 11px, en 169자에 하한 9px이다. 10/27에 클래식 카드 프레임(`card_scene.tscn`)과 설정의 "카드 프레임" 항목을 없앴다. 카드 장면은 `card_scene_v2` 하나뿐이다.

## 동작 과정

1. 새 UI 글자는 숫자를 직접 쓰지 말고 `SacredTheme.FS_TEXT` 또는 `FS_SMALL`을 쓴다.
2. `tests/test_font_size_floor.gd`가 `scenes/`·`autoload/`의 리터럴 크기를 정적으로 검사한다. 대상은 `font_size` override, `fit_text` 최소값, `_make_label`, 테마 변형이다.
3. 화면 비교는 `tests/capture_ui_text_scenes.gd`를 `tools/run_live_balance_checks.sh --rendered`로 실행해 확인한다. 출력 위치는 `STSL_UI_CAPTURE_OUTPUT`으로 바꿀 수 있다.

## 실무 고려사항

- 렌더 테스트 창: macOS는 시작 위치(`--position`, `initial_position`)를 화면 안으로 당긴다. 또 Godot은 완전히 가려진 창은 그리지 않는다. 그래서 실행기가 `tools/offscreen_window.gd`를 autoload로 끼워 넣어, 매 프레임 창을 화면 오른쪽 아래에 2px만 걸치게 옮긴다. `no_focus`·`borderless`도 같이 적용한다. 캡처는 1920×1080 그대로다. Godot은 macOS에서 시작할 때 스스로 앱을 활성화한다. 그래서 실행기는 직전 앞 앱을 기억해 두고, 시작 후 10초 동안 Godot이 앞으로 나오면 원래 앱을 다시 활성화한다. 그래도 0.1~0.3초는 포커스가 넘어간다. `open -g`로도 막지 못했다.
- `run_live_balance_checks.sh`는 `rg`로 오류를 판정한다. Claude Code 셸에는 `rg`가 없어 판정이 조용히 건너뛰어진다. 결과는 로그의 passed/failed 줄로 확인한다.
- 캡처 스크립트는 이벤트(`pending_event`)·카드 선택(`card_rewards`) 상태를 미리 채워 19장을 찍는다. 대상은 메인·크레딧·튜토리얼·영웅/챕터 선택·맵·설정·상점·휴식·이벤트·카드 선택/강화·챕터 완료·게임오버·도감·전투(기본/상태/덱 보기)다.
- 10/26 점검에서 글자 하한으로 깨진 화면은 없었다. 남은 가독성 문제는 대비다. 붉은 HP 바 위의 황동색 HP·방어 숫자와 하늘 배경 위의 적 이름이 잘 안 보인다. 10/26에 시안을 만들었다. 이름은 황동색 그대로 두고, HP 숫자는 밝은 색으로 바꿨다. 이름·HP·방어 숫자에는 어두운 외곽선(5px)을 넣었다(`_outline_hud_label`). 같은 날 카드 강화 화면도 고쳤다. 그리드가 실제 카드 폭(모던 196px)을 쓰는데 940px 영역에 담겨 오른쪽 열이 잘렸다. 지금은 영역을 그리드 너비에 맞춘다. 두 수정 모두 사용자가 수정 전후 캡처를 비교한 뒤 채택 여부를 결정한다.
- 2026-10-26 검증 결과
  - 하한 검사 106 통과
  - 사용 전 확인 패널 134 통과
  - 튜토리얼 통합 312 통과
  - small-number UI audit 52403 통과

## 흔한 오해

- "16px면 충분하다"가 아니다. 1080p 설계 기준의 하한일 뿐이다. 더 키우려면 화면별 배치를 같이 고쳐야 한다.
- 좁은 칸의 긴 이름은 글자를 줄이지 않는다. 표현 방식을 바꾼다. 전투 왼쪽 위 행동 순서 큐는 14px 이름이 두 줄로 늘어나 보기 흉하다는 사용자 피드백을 받았다. 그래서 10/26에 48px 초상화 칩으로 바꿨다.
  - 일러스트 위쪽 가운데의 너비 55% 정사각을 잘라 쓴다.
  - 테두리 색은 진영(영웅 황동, 적 적색)이고, 현재 차례는 굵은 테두리다.
  - 전체 이름은 툴팁으로 보인다.
  - 일러스트가 없으면 이름 앞 두 글자를 보여준다.
