## 신뢰성과 비교 범위

- 현재 브랜치·미커밋 코드를 보존하고 별도 임시 폴더에서 실행했다. 공통 런타임은 `e900b44`, 카드/손패 타깃만 `afe1bee→1710ca6`의 실제 스크립트로 바꿨다. 여러 기능이 함께 바뀐 전체 과거 빌드가 아니라 **컴포넌트 A/B**다. 조우도 `edb3c65`의 기존 공식을 공통 evaluator에 재현하고 `07d36ff`의 실제 이력 선택기와 비교했다.
- M2·RAM16GB·macOS27.0.1·Godot4.7.2 Mono·Metal Mobile. 동일 자산/해상도/카드 상태/입력, 조우 동일seed/경로. 모든 게임 테스트 Dummy/뮤트·격리 저장. 규칙/화질/기능 축소 없음. export-release 결과는 아니다.
- 시간은 ABBA×3, arm별6프로세스·10회 워밍업 뒤30 batch씩 총180개. 첫5장 setup은 application-cold로 분리해 **p50 146.133→124.808ms**, 각6개만 관측했다. 디스크 cold나 전체 로딩 시간은 아니다. p95·min/max·프로세스별 결과는 보고서/JSON에 있다.
- 포커스는 카드 전179/180·후180/180, 손패 전149/180·후131/180으로 완전 통제되지 않았다. 모든 표본을 보존했다. 카드 focused-only 민감도 p50 **12.954→0.223ms**도 공개했다. 종료 시 배터리·저전력 설정을 확인했으며 전체 실행 내 전력/온도/클럭 연속 기록은 없다.
- 조우는3600고유 경로를 정순/역순 두 번 실행해 시퀀스까지 일치했다. 반복을7200독립 표본으로 부풀리지 않는다. 규칙/실제 저장 검사 양쪽46통과·실패0. 카드/손패 후컴포넌트 프로젝트는 각각42회귀·실패0.
- 감소율은 `(전−후)/전×100`. 시간비는 `전/후`이며 FPS배수와 다르다. 비율의 절대차이는 `%p`. 예: 카드 `(12.949−0.223)/12.949×100=98.2779%`, 조우 `(7576−833)/7576×100=89.0048%`, 손패 `(900−0)/900×100=100%`.
- **당시 실측/이번 신규 실행/코드 산출을 구별**한다. 캐시 조합 상한·설정 해상도 자체를 실측 절감량으로 세지 않았다. 게임 전체 FPS·GPU·메모리·할당바이트 개선은 측정하지 않았다.

## 기존 기록과 다른 점

카드의 당시 p50 **7.589→0.158ms** 대신 이번 **12.949→0.223ms**를 정본으로 쓴다. 과거와 카드 데이터·배치 스케일·반복 수/세션 구성이 다르고 당시 전력·OS 세부 기록이 없어 단일 원인을 확정할 수 없다. 현 배터리/저전력 설정과 후반 세션 변동은 확인했지만 그 때문이라고 단정하지 않는다. 소스에서 원형 생성 알고리즘은 캐싱 전후 유지됨을 확인했다. 당시 개별 시간 배열도 없어 동일 분포를 다시 구성할 수 없다. 옛 수치에 맞춰 조건·표본을 고르지 않았다.

손패는 과거150→0/30회와 신규900→0/180회의 **갱신당5→0**이 일치한다. 조우는 과거7576/7591/833과 새 실행이 정확히 일치했다. [이전 조사 원문](정량적_문제해결_사례_이전조사.md)은 기록 보존용이며 신규 측정의 정본이 아니다.

## 포트폴리오 문장 초안

1. 카드: “카드 UI의 반복 장식 생성 병목을 AI 보조로 분석하고 불변 장식 캐싱을 적용했다. M2·Godot 렌더링 컴포넌트의 교차 반복 측정에서 카드5장 warm 갱신 p50을12.949ms에서0.223ms로98.28% 줄였고 전후 실제 화면의 픽셀 일치를 검증했다.”
2. 손패: “동일 손패의 중복 재구축을 개선해 고정5장 손패180회 갱신에서 새 카드 루트와 삭제요청을 각각900개에서0개로 줄였다. 실제 카드 씬의 표시 동일성과 순서·턴 전환 시 필요한 재구축도 확인했다.”
3. 조우: “조우 중복을 가중치와 이력 부재로 분리해 검증했다. 동일3600개 액트 경로에서 가중치만 바꾸면 반복이 줄지 않았지만 이력 도입 후 일반 조합 재등장은7576회에서833회로89.00% 감소했으며 난도자격·저장복원·결정적 재현성을 확인했다.”

이 문장은 **AI 보조 개인 프로젝트**라는 맥락과 함께 사용한다. 사용자 기여로 확인되는 것은 문제 제기·우선순위/정책 결정·적용/무음/검증 요청이다. 분석·구현·자동 실행·근거 문서화는 AI가 수행했다. 사용자 직접 코드 작성/알고리즘 고안/검토 시간 비율은 확인되지 않아 주장하지 않는다. Git Author만으로 직접 구현량을 확정하지 않는다.

## 추천에서 분리한 후보

반복 그림/하트 로드 시간은 당시 전후 focus 차이·작은 표본 때문에 강한 정량 성과로 추천하지 않는다. startup/prefetch는 비용 이동을 전체 로딩 단축으로 포장하지 않는다. GPU의0ms는 측정 불능이지 병목 없음이 아니다. 테스트 통과 개수·봇 완료 개수만으로 성능이나 오류 발생률 개선을 만들지 않는다. 조작 단계·사람 반복작업 시간·전체 FPS·메모리의 전후 근거는 부족해 수치를 추가하지 않았다. 자세한 후보 검토는 보존한 이전 조사에 있다.
