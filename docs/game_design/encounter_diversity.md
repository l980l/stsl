# 런 내 조우 중복 최소화 — 2026-10-17

사용자 승인: 난도 안의 미등장 일반 조합 우선, 동일 조합 연속 방지, 후보 소진 시 최소 사용 조합 재사용. 정예에도 같은 원칙을 적용한다. 같은 전투 안의 동일 종 무리는 보존하고 적 수치·보스·저작 편성을 변경하지 않는다.

## 규칙과 저장

- 일반 난도 진행도는 실제15층 맵의 마지막 일반전 가능 층12에 맞춘다. 층13휴식·14보스는 기존대로다. 기존 거리<4인 양의 가중치 창을 유지하고, 처음 보는 적을 찾으려고 창 밖의 고난도 조합을 뽑지 않는다.
- 같은 신화/종류의 직전 조합을 후보에서 제외한다(다른 후보가 있을 때). 남은 후보 중 조합 등장 횟수가 최소인 것, 다음으로 종의 과거 전투 등장 합계가 최소인 것을 고르고, 동률에만 기존 난도 가중 랜덤을 사용한다.
- 한 전투에서 같은종3마리는 종 이력1회로 센다. 조합 키는 순서를 정렬하지만 중복 수는 유지하므로 순서만 바꾼 조합은 새 조합이 아니다.
- 후보가 소진되어도 난도 밖으로 확장하거나 전투 생성을 막지 않는다. 최소사용 후보를 재사용한다. 후보가 사실상1종뿐이면 연속 재사용은 불가피하다. 절대적인 최대2회 보장이 아니라 반복 최소화다.
- 실제 일반/정예 선택에서만 이력을 소비한다. 맵 생성/미방문 분기/보스/전투 중 소환은 이력을 소비하지 않는다. 이벤트가 일반/정예 전투를 요청하면 같은 선택기로 이력을 공유한다.
- 런 시작에서 초기화하고 액트 전환에서는 유지한다. `GameManager.to_dict/from_dict`에 신화 순서와 조우/종/직전 이력을 추가해 저장 복원한다. 기존 컨테이너 버전은 유지한다. 옛 저장에는 이력이 없으므로 과거 전투를 복원했다고 주장하지 않고 빈 이력에서 시작한다. 기존에 저장하지 않던 신화 순서는 옛 저장에서 복구할 수 없고 해당 챕터 풀을 새로 배정한다. 전역 RNG 상태까지 저장하는 변경은 아니다.

## 사전 검증 계약

실제 GameManager로 난도 창 준수·미등장 우선·연속 금지·풀소진·1후보/동일별칭·무리중복·신화 구분·정예·이벤트·새런 초기화/액트 유지·JSON 왕복/옛저장/잘못된선택 이력을 검사한다. 실제 플레이 저장은 건드리지 않고 Dummy/무음/격리 user://를 사용한다.

반복 지표는 6신화×3액트×시드0..99×실제맵 좌/우 경로=3600개의 액트 경로 fixture에서 세 방식(이전9층가중치/새12층가중치만/새12층가중치+이력)을 비교한다. 분모는 각 방식의 선택된 일반/정예 전투 수, 분자는 조합 재등장·직전 같은 종류 조합 반복·종 재등장이다. 같은종 무리 내부 중복은 제외한다. 맵/경로는 같은 입력으로 고정하며, 경로/실제선택 궤적 중복은 해시로 보고한다.

합격 조건은 새 선택의 난도 창 위반0·대안이 있는 연속중복0·저장 이력 보존이며, 기존과 대비한 조합 반복/고유조합 차이를 보고한다. 샘플은 조우 선택만 실행하고 전투 승패/체감난도/재미를 측정하지 않는다. 이벤트 발생/소환/최적경로 선택은 이 표본의 대상이 아니다. 몬스터 수치는 같아도 초중후반 노출 빈도가 달라져 기존 밸런스 표본의 출현 분포와 같다고 주장하지 않는다.

## 구현과 검증 결과

GameManager에 일반/정예 공용 이력 선택을 연결하고 새 런 초기화·액트 유지·이벤트 공용·저장/불러오기를 구현했다. 맵 노드의 오래된9층 보스 주석도 실제14층 기준으로 고쳤다. 정상 저장에는 신화 순서를 함께 보존하므로 재시작 후 다른 신화 풀로 바뀌어 이력 제한을 우회하지 않는다.

46개 필수 검사 통과·실패0. 순서만 다른 조합의 동일성, 풀 소진/별칭뿐인1후보, 무리의 종1회 집계, 정예 첫3회 미등장, JSON 복원과 **실제 격리 SaveManager 파일 저장/불러오기**, 새런/액트/이벤트/보스/미방문맵, 옛저장/잘못된 이력까지 실행했다. 개발 중 동적 노드에서 typed Array를 전달하는 fixture 초기화 오류는 수정했고 필수검사 수 검증으로 중단된 검사가 통과로 합쳐지지 않게 했다.
