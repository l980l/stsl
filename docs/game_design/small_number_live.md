# 작은 정수 수치 체계 — 실제 플레이 적용

2026-10-15. 사용자 “남은 것들도 전부 적용해” 승인에 따른 **전체 단위 전환**이다. 과거 v1/v2 비교 실험은 당시 후보 기록으로 보존한다. 이번 변경은 실제 `pearlfish/project.godot`의 기본 플레이에 적용되며, 모든 조합의 최종 밸런스 확정을 뜻하지 않는다.

## 적용 범위

- 카드 216종·0/1강: 실제 생성/보상/도감/저장 복원에 같은 작은 정수 정의를 사용한다. 강화는 명시된 고정 수치·대상·규칙으로 복원하며 작은 값에 예전 퍼센트 강화를 다시 적용하지 않는다.
- 영웅 시작 HP 100. HP·피해·방어·회복·독·힘·매혹은 차원에 맞춰 약 1/10로 환산한다. 매혹 기본 임계는 10이며 저항·감소량도 같이 변환한다. 에너지·장수·사기·병사 수·속도·기간·골드·퍼센트·동일 차원의 피해계수는 일괄 나누지 않는다.
- 일반·정예·보스 192종: 일반/페이즈 패턴, 차지 후속 의도, 카드 카운터, 사망 효과, 소환, 페이즈 버프, 시그니처를 연결했다. 막 난이도 배율 적용 후 변환하며 도감→전투 경계에서도 재환산하지 않는다.
- 유물, 실제 선택되는 6개 이벤트 풀, 상점 회복, 휴식, 튜토리얼 3개 레슨 및 관련 표시를 연결했다. 빈 status_type을 독으로 처리하던 유물도 독 수치를 환산한다.
- 세이브 컨테이너 version 2는 유지하고 `combat_unit_version: 2`로 단위를 구분한다. 옛 저장은 **읽을 때 메모리 사본의 HP만 한 번 변환**하고 원본 파일은 그대로 둔다. 다음 정상 저장에서 새 단위를 기록한다. 덱은 카드 이름·소유자·강화로 최신 정의를 복원하며 미등록 카드에는 덱 단위 표지를 사용한다. 미지원 미래 버전은 파일을 삭제하지 않고 거부한다.

## 반올림과 강화 정책

- 표시만 줄인 것이 아니다. 저장되는 HP·카드 효과·최종 피해·방어·독 수치는 정수다. 퍼센트 계산의 내부 중간값은 허용하되, 작은 수치에서는 공격자/피격자 단계에서 거듭 버리지 않고 최종 피해에서 한 번 정수화한다. 양수 피해가 1 미만이면 1, 명시 무적·진짜 0 피해는 0이며 이후 방어로 전부 막힐 수 있다.
- 사막 기마·독침·나일의 분노 등 v2 개별 조정은 유지한다. 나일의 안개 강화는 독 1 유지/방어 +1, 독의 정화 강화는 독 2 유지/아군 전체 정화로 바꿔 독의 3회 피해를 과도하게 늘리지 않는다.
- 반올림으로 무효가 된 매턴 독/방어/팀 회복 권능 강화는 매턴 1→2처럼 영구 배증하지 않는다. 기본량을 유지하고 **본인 권능의 매 5번째 발동에 +1**을 준다. 카드 설명과 활성 권능의 발동 진행 수에 표시하며 다른 영웅 차례에는 진행하지 않는다. 원래부터 유효한 명시 강화는 유지한다.
- 반복 휴브리스·음양·시간 제한 힘 증가는 누적한 옛 증가량을 정수 단위로 지급한다. 휴브리스 5회당 힘 1, 음양 공격형 10회당 힘 1, 시간 제한 광폭화 2회당 힘 1이다. 매번 최소 1로 올려 반복 성장률을 5~10배 높이는 방식을 피했다. 유물의 처치/전투 수 보너스도 합계에서 환산한다.
- 실제 큐를 쓰는 화면 밖 검사에서 발견한 기절/병사 연출의 null Tree 타이머를 보완했다. 영웅 차례의 비동기 처리도 기다려 다음 유효 입력까지 진행한다. 피해·승리 조건을 봇을 위해 바꾸거나 강제 승리시키지 않는다.

## 검증 계약과 재현

```sh
bash tools/run_live_balance_checks.sh run_small_number_live run_small_number_progression run_enemy_small_numbers run_enemy_small_number_smoke test_tutorial_integration
STSL_LEGACY_COMBAT=1 bash tools/run_live_balance_checks.sh test_runner
bash tools/run_small_number_simulation.sh --all-enemies --seeds=101 --cap=192
bash tools/run_small_number_simulation.sh --seeds=101 --power-turns=3 --weak --vulnerable --poison-ticks=3
```

모든 실행기는 Dummy 오디오·별도 user://를 사용한다. 사용자 저장/설정을 덮어쓰지 않으며 성능 프로파일링은 재개하지 않았다. `STSL_LEGACY_COMBAT=1`은 과거 회귀·대조군 전용이며 일반 플레이용 저장을 이 모드에서 섞어 사용하지 않는다.

검사의 단위는 독립 플레이어가 아니라 고정 입력의 규칙 사례/궤적이다. 실제 ATB 비교는 3인 시작 덱 한 조합·0강·시드101·무치명타·손패 순서대로 첫 사용 가능 카드/첫 생존 적 정책이다. 카드 효과 검사는 216종×0/1강×빈/축적 자원×1/3인팀=1728쌍이다. 추가 스트레스에서는 약화/취약을 고정하고 권능 콜백 3회·독 콜백 3회를 실행하며, 이를 온전한 3개 actor 턴으로 해석하지 않는다.

원시 결과와 소스 SHA·dirty 상태는 무시되는 `log/small-number-simulation/`, `log/live-balance/`, `log/campaign-bot/`에 보존한다. 오래된 짧은 cap/오류 있는 실행은 최종 결과에 합치지 않는다. cap은 패배나 불가능 판정이 아니다.

전체 데이터/실행 경로 전환과 전체 재미·난이도 완성은 구별한다. 초반/중반의 쉬운 전투 모두 승리만으로 게임 난이도를 합격시키지 않는다. 덱 선택·영입·유물·다중 적·치명타·영웅 조합 전체의 분포와 사람의 계산 편의·전투 길이는 추가 플레이가 필요하다. 실제 씬 봇은 연출의 전역 난수 영향도 받아 같은 시드의 서로 다른 실행을 정확한 쌍 비교로 간주하지 않는다. 마지막 보스에서 패배한 캠페인 사례와 큰 HP/차례 차이는 유지하고, 단위 전환이 끝났다는 이유로 지우지 않는다.
