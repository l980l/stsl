# 작은 정수 후보 — 다중 턴 전투 시뮬레이션

2026-10-14. 기본 게임/플레이어 세이브를 전환하지 않고, 원본과 작은 정수 후보의 실제 전투 규칙을 비교하는 로컬 실험이다. [후보의 단위 계약](small_number_balance_profile.md)을 이어서 검증한다. 성능 프로파일링이나 사람 플레이의 재미 평가가 아니다.

## 질문과 판정 경계

- HP/공격/방어/독/매혹을 함께 축소했을 때 같은 덱·적·정책에서 승패, 전투 길이, 정규화한 남은 HP가 달라지는가?
- 특히 여러 번의 정수 반올림, 토큰의 최소1 피해, 권능 누적, 명시 강화가 즉시 효과 검사를 넘어 어떤 차이를 만드는가?
- 승패가 뒤집힌 쌍, 전투 길이 차이가 큰 쌍, 남은 HP 차이가 큰 쌍을 다음 조정 대상으로 기록한다. 제한 종료는 패배/불가능으로 취급하지 않고 따로 보고한다. 사용자가 요청한 것은 테스트이므로 이 실행 중 카드/몬스터 수치를 자동 재조정하지 않는다.

## 증거 계약

평가 단위는 같은 영웅·덱·등급·몬스터·난수·봇 정책의 원본/후보 **전투 한 쌍**이다. 실제 BattleManager/DeckManager를 사용한다. 외부 고정 DPS나 평균 방어 모델을 실제 게임 결과인 것처럼 사용하지 않는다.

보고서는 포함/제외한 콘텐츠와 이유, 승리/패배/제한 종료의 분자·분모, 영웅/등급/적별 구간, 전투 길이·남은 HP 차이, 원시 실행 기록, 고유 궤적/중복 수, 소스 SHA256·기준 커밋·dirty 상태를 보존한다. 같은 궤적의 시드 반복을 독립 표본인 것처럼 세지 않는다.

몬스터 변환은 시뮬레이션 내부에서 명시적으로 수행한다. 실제 게임의 몬스터 공장·유물·이벤트·세이브가 전환된 것은 아니다. 일반 몬스터 전투와 시작 덱만으로 두 챕터 완주, 보스·영입·유물 시너지·보상 경제·모든 카드 조합의 밸런스를 입증하지 않는다. 봇 선택의 한계와 사용한 턴 스케줄을 결과와 함께 명시한다.

## 재실행

```sh
bash tools/run_small_number_simulation.sh
```

실행기는 새 `STSL-tutorial-validation-simulation-*` 프로젝트를 만들어 저장 경로를 격리하고, Dummy 오디오로 시작부터 무음 실행한다. 사용자 project.godot/세이브/음량을 변경하지 않는다. 보고서는 Git에서 제외된 `log/small-number-simulation/run-*` 아래에 보존한다. 기존 즉시 효과 검사와 다중 턴 검사를 순서대로 실행하며 오류 로그/보고서 미생성을 성공으로 취급하지 않는다.

## 구현

- `tools/evaluate_small_numbers.gd`: 전체216개 카드0/1강의 즉시 효과 비교.
- `tools/simulate_small_number_battles.gd`: 다중 턴 전투 비교와 제외 이유/한계 기록.
- `tools/run_small_number_simulation.sh`: 저장/소리 격리·보고서 보존·실패 감지.

밸런스 수치의 기본 적용·커밋·푸시는 이 테스트에 포함하지 않는다.

## 최종 실행 조건

- Godot4.7.2, 기준 커밋 `0a916bb9d6f18f10861c4ed003fafc9661ddffb9` + dirty 로컬 변경. 원본/후보에 치명타 비활성 테스트 훅을 동일하게 적용했다.
- **실제 ATB**: `start_player_turn()`과 `end_player_turn()`을 사용한다. 적 행동을 수동으로 끼워 넣지 않으며 카드 비용·드로우·손패 선택·독/권능/병사·속도 기반 턴 큐를 실제 BattleManager가 처리한다.
- 시드101/202/303, 모든 카드0강 또는1강, 최대24회 영웅 입력 차례. 제한에 도달하면 다음 액터로 큐를 진행하기 전 중단한다. 제한 상태는 현재 차례 중간이므로 완결 전투의 승패/잔여 HP와 섞지 않는다.
- 영웅6명의 실제 시작 덱(각10장), 추가로 사막 기마/나일의 분노를 시작 덱에1장 더 넣은 두 보상 탐침 덱(각11장). 보상/경제 시뮬레이션이 아니라 해당 카드의 다중 턴 관측용이다.
- 6개 신화의 일반 몬스터120종을 고유 이름으로 중복 제거 후 검사. **15종 포함,105종 제외**: 시그니처 활성102종, 지원하지 않는 의도3종(speed_penalty/remove_card/SPECIAL weak). 제외 이유는 원시 JSON에 남긴다. 테스트마다 단독 영웅·몬스터1명, 최대 HP로 시작하며 유물·메타 성장·막별 난이도 보정은 없다.
- 정책은 손패 순서대로 첫 사용 가능한 카드를 사용하고 첫 생존 적을 겨냥한다. 버리기 선택도 손패 첫 카드다. 최적 플레이를 탐색한 것이 아니다.

초기 개발용 고정 교대 샘플은 실제 ATB 결과와 혼합하지 않았다. 최종 아래 결과는 실제 ATB 및 수정된 스냅샷 버전에 한정한다.

## 결과

15종 × 8덱 구간 × 2강화 등급 × 3시드 = **720쌍/실행1440전투**. 구간당90쌍이며 시작 덱540쌍, 보상 탐침180쌍이다.

| 관측 | 원본 | 작은 정수 후보 |
|---|---:|---:|
| 승리 | 720/720 | 720/720 |
| 패배 | 0/720 | 0/720 |
| 제한/미완료 | 각각0/720 | 각각0/720 |

- 승패 뒤집힘0/720. 영웅 입력 차례 수 동일679/720, 후보가 더 짧은 경우41/720, 더 긴 경우0/720. 후보−원본 차이는 **−3~0차례**, 중앙값0이다.
- 원본 잔여 HP를10으로 나눈 값과 후보의 차이는 **−0.5~+7**, 중앙값0이다. 이 소수는 분석값이며 후보 인게임 HP/피해는 정수다. 최대 차이7은 최대 HP100 기준7%p다.
- 최대 HP 차이: 클레오파트라1강 시작 덱 vs 불교 야차, 시드101. 원본930HP→정규화93, 후보100, 후보 입력 차례1회 감소.
- 최대 차례 감소: 나일의 분노1강 탐침 vs 도교 도제, 시드303에서3회 감소. 비용/카드 선택 정책이 동일해도 이산 피해·독의 처치 임계점이 달라질 수 있다는 관측이다. 해당 표본만으로 원인 카드 하나의 전체 기여나 우월 전략을 확정하지 않는다.
- 스냅샷 기반 고유 쌍 궤적663개, 동일 관측 궤적 반복57개. 이는 고정 시드·정책의 관측 기록 수이고 독립 플레이어 표본663명이라는 뜻이 아니다. 손패/드로우/버림/소멸 순서·에너지·상태·권능을 복사해 기록하며, 살아 있는 Dictionary를 뒤에 수정해서 과거 기록이 바뀌지 않도록 검사했다.
- 즉시 효과216개0/1강 비교도 재실행:1728쌍, 기존 사막 기마 이상치4쌍·선택 미완료8쌍 유지. 다중 턴 탐침의 쉬운 전투 승리가 이 미해결 사항을 해결한 것으로 간주하지 않는다.

## 해석과 다음 판단

현재 포함한 초반 일반 적과 단순 정책에서는 수치 축소로 패배가 새로 발생하지 않았다. **전체 밸런스 합격은 아니다**. 모두 승리한 쉬운 표본은 장기전 누적·어려운 전투의 생존 경계에 민감하지 않다. 일부 클레오파트라 구간에서 후보가 더 빠르거나 HP를 더 남기는 차이는 추가 검토 대상이다.

다음 비교 우선순위는 사막 기마 강화폭, 클레오파트라의 독/매혹 처치 임계점, 그리고 제외된 시그니처·정예·보스·복수 적·팀 조합이다. 이를 포함하려면 해당 데이터와 하드코딩 전투량의 작은 단위 변환을 먼저 검증해야 한다. 이번 실행은 수치를 다시 조정하거나 기본 게임/세이브를 전환하지 않았다.

## 검증과 원시 근거

- 최종 격리 실행기 성공, 최종 instant/battles 로그의 엔진 오류/경고0.
- 기존 전체 회귀4060 통과/실패0. 일부 RNG 기반 검사 수는 실행마다 달라질 수 있으므로 이전 검사 수와 단순 차감하지 않는다.
- 화면 밖 실제 병사2명 공격 검사2개 통과(기존25×2/후보3×2), 기록 불변성·손패 순서 등 스냅샷 검사5개 통과. 병사 연출 타이머는 화면 트리에 있을 때만 기다리도록 최소 수정했으며 실제 피해 루프는 변경하지 않았다.
- 제한1회·시드101의 별도 기능 검사240쌍: 원본114승리/126제한, 후보119승리/121제한, 패배/미완료0, 실제 입력 차례 최대1. 제한을 패배로 잘못 기록하거나 다음 차례까지 진행하지 않는 것을 확인했다. 기본 실행과 겹치는 시드이므로 추가 독립 표본으로 합산하지 않는다.
- 원시 근거: `log/small-number-simulation/run-8CjAaw/instant.json`, `battles.json`, 각 `.log`. Git에서 제외한 로컬 결과지만 위 실행기로 재생성할 수 있다.
- battles JSON SHA256: `d94ef0a28b4cbf7e7ca530121ad483371f167e21beb1210dbaf66993efe1577e`; 시뮬레이터 소스 SHA256: `dcf379c446f7b9591164c6d9be9e536e5c29da6ff983b8efa63b190506178a0a`. 실제 사용한 핵심 규칙/카드/적 공장의 개별 해시는 JSON의 `source_sha256`에 있다.
- 개발 중 잘못된 비동기 검사 호출로 발생한 중간 parse 오류는 수정했으며 최종 실행 증거에서 제외했다. 이전 고정 교대/스냅샷 수정 전 결과도 최종 결과와 합치지 않는다.
