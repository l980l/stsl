# 작은 정수 전투 수치 — 후보 v1과 검증 계약

2026-10-13. 사용자 승인에 따른 **후보 구현·비교 단계**다. 일반 플레이의 카드/몬스터/세이브는 아직 기존 단위다. 표시만 작게 속이는 방식이 아니라, 별도 후보 Resource와 실제 BattleManager에서 작은 정수로 계산한다. 성능 측정은 재개하지 않았다.

## 단위와 강화

| 항목 | 후보 원칙 | 예시 |
|---|---|---|
| 최대/현재 HP, 피해, 방어, 회복, 독 피해, 힘 | 약 1/10, 결과 정수 | HP 1000→100, 공격 100→10 |
| 매혹량·임계치·저항·소비 한도 | 함께 1/10 | 기본 임계 100→10, 저항 20→2 |
| 사기·병사·에너지·장수·횟수·지속·속도·골드 | 같은 단위 유지 | 에너지3, 사기3 그대로 |
| 퍼센트·비율 | 역할상 필요한 계수 유지, 설명은 정수 % | 방어 소비 ×1.5→150% 표시 |
| 토큰/사기/손패당 피해·방어 | 결과의 단위에 맞춰 축소 | 사기당 방어50→5 |
| 매혹당 피해 계수 | 매혹과 피해가 같이 줄어들므로 유지 | 매혹당 피해4→4 |
| 방어당 피해 계수 | 방어와 피해가 같이 줄어들므로 유지 | 120%→120% |

초기 양수 환산은 반올림(절반 올림), 최소1, 기존0은0이다. 이것은 완성된 밸런스가 아니라 첫 후보를 만드는 규칙이다. 특히 옛3→새1은 3배 이상의 효율 변화를 만들 수 있으므로 개별 검토 대상이다. 부동소수 비율이나 연출 시간까지 제거하는 것은 목표가 아니다. 플레이어가 보는 전투량과 실제 HP/피해 결과를 정수로 유지한다.

현재216개 카드의 0강·1강은 실제 v3 생성 결과와 GameManager 강화 결과를 복제해 환산한다. 비용·소멸/보존/내재·드로우 등 기존 강화도 보존한다. 반올림으로 **카드 전체 강화가 무효**가 되는 경우에만 한 항목에 고정+1을 준다. 모든 항목을 각각+1로 올리지 않는다. 이것만으로 다단히트나 여러 효과의 밸런스가 확정되지는 않는다.

## 로컬 비교 프로필

- 가설: 역할과 자원 소비를 보존하면서 암산 단위를 줄일 수 있다.
- 동일 입력: 카드216 × 0/1강 × 빈/축적 자원 × 1/3인 팀 = **1728쌍**. 각 쌍은 같은 난수 초기값73013, 적2명, 치명타/시그니처 비활성이다. 여러 독립 플레이 표본으로 취급하지 않는다.
- 축적 자원: 사기3, 토큰3, 방어80→8, 순교은행150→15, 독20→2(3턴), 매혹40→4, 손패3·선행 사용/드로우3. HP500/1000→50/100, 에너지3이다. 드로우용 빈 효과 카드10장을 준비한다.
- 실제 `_apply_card_effects`를 호출하며 HP·방어·독·매혹의 즉시 변화와 등록된 권능/사기/에너지를 기록한다. 임의의 별도 피해 공식을 만들어 실제 규칙인 것처럼 사용하지 않는다.
- 이상치 기준: 0인 결과가 새로 생기거나 0이 아닌 결과가 소실되면 무조건 검토 대상이다. 그 외 HP 단위는 이전 결과/10과 비교해 **절대 차이1 이하 또는 상대 차이15% 이하**, 에너지·장수·사기·토큰 변화는 정확히 동일해야 즉시 효과의 비교 범위 안이다. 이 기준은 진단용이다. 강화를 없애거나 카드 개성을 바꿔 점수만 통과시키지 않는다.
- 보고서에는 카드/등급/상태/팀별 원본 결과, 비교 차이, 변환 미분류 항목, 위험 메모, 기준 커밋·dirty 상태·실제 소스 SHA256을 남긴다.

### 현재 검증 범위의 한계

즉시 효과가 없는 권능은 등록 데이터만 기록하며 전후 권능/기타 상태 전체를 자동 비교하지 않는다. 부활/사망, 다음 턴 권능 발동, 손패 선택 완료, 실제 비용 지불을 포함한 플레이 경로, 유물/이벤트/몬스터 시그니처, 전투 승률·소요 턴 수는 이 비교로 검증하지 않는다. 적 HP/의도/저항은 합성 fixture에서 양쪽 단위를 맞춘 것으로 실제 몬스터 공장 전환을 입증하지 않는다. 두 자원 상태·한 팀 조합씩만 있으므로 영웅 조합 전체를 대표하지 않는다. 차이가 작은 경우나 효과0인 경우를 자동으로 '밸런스 합격'이라 부르지 않는다.

## 구현 위치와 실행

- `resources/balance/small_number_profile.gd`: 원본을 변경하지 않는 후보 생성, 이중 변환 방지, 차원별 필드 분류.
- `autoload/battle_manager.gd`: 기본 `combat_unit_divisor=1`. 후보 검사는10으로 설정하고 **하드코딩된 전투량만** 맞춘다. 전달된 카드/의도 값은 다시 나누지 않는다.
- `tools/evaluate_small_numbers.gd`: 비교 JSON 생성. 기본 출력은 격리 프로젝트의 `user://small_number_comparison.json`.
- `tests/test_small_number_profile.gd`, `tests/test_small_number_runtime.gd`: 후보 데이터·매혹 임계/미리보기·사기 시너지·순교은행 규칙 회귀 검사. 전체 테스트 실행기에 포함했다.

사용자 세이브와 설정을 공유하지 않는 `STSL-tutorial-validation-*` 프로젝트에서 실행한다. 예시의 `TEST_PROJECT`는 실제 격리 프로젝트 경로로 지정한다.

```sh
/Applications/Godot_mono.app/Contents/MacOS/Godot --headless --audio-driver Dummy --path "$TEST_PROJECT" --script res://tests/run_small_number_profile.gd
/Applications/Godot_mono.app/Contents/MacOS/Godot --headless --audio-driver Dummy --path "$TEST_PROJECT" --script res://tests/run_small_number_runtime.gd
/Applications/Godot_mono.app/Contents/MacOS/Godot --headless --audio-driver Dummy --path "$TEST_PROJECT" --script res://tools/evaluate_small_numbers.gd -- --output=/tmp/STSL-small-number-comparison.json --revision=0a916bb9d6f18f10861c4ed003fafc9661ddffb9 --dirty=true
```

## 기본 게임 전환 전에 필요한 작업

1. 영웅·모든 적 공장(HP/의도/페이즈 버프/저항), 유물·이벤트 HP 비용/회복, 튜토리얼·상점 회복까지 **한 번만** 같은 단위로 전환. 에너지/속도/퍼센트 의도를 일괄 나누지 않는다.
2. SaveManager 현재version2에서 버전을 올리고 이전 영웅의 max/current HP를 정확히 한 번 변환하는 정책과 회귀 검사를 추가. 카드는 이름으로 최신 정의를 복원하므로 불필요한 재환산 금지. 기존 런을 지금 자동 변환하지 않았다.
3. 독 조건 `has_poison_5/10`처럼 새 단위에서1로 합쳐지는 임계값, 최소1 토큰/매혹 시너지, HP 소비의 반올림을 개별 재설계.
4. 실제 비용 지불·선택·여러 턴·사망/부활·유물/이벤트/시그니처를 포함하는 소형 정수 회귀 검사 후, 무음 격리 캠페인 봇으로 같은 시드의 챕터1/2를 비교. 이번에는 성능 프로파일링을 하지 않는다.
5. 승률 외에 패배 위치, 턴 수, 영웅별 기여·피해/방어/회복, 선택 편향·미사용 카드까지 확인하고 플레이 감각은 사람 플레이로 검증.

전투를 더 짧게 만드는 튜닝과 숫자를 작게 만드는 단위 전환은 별도다. HP와 공격을 함께1/10으로 줄이는 것만으로 전투가 빨라지는 것은 아니다.

## 1차 결과와 개별 후보 조정

최종 기준은 main `0a916bb9d6f18f10861c4ed003fafc9661ddffb9` + 로컬 변경이다. 전체 회귀 **4044 통과/실패0**, 전용 후보 **1110 통과/실패0**(전체와 중복), 단위 런타임9개 통과. 전체 실행 로그에 엔진 오류/경고는 없다. 에디터 import 단계에는 기존 아트 폴더의 중첩 project.godot 경고가 있으며 이번 작업에서 그 폴더를 변경하지 않았다.

| 카드 | 작은 정수 0강 → 1강 후보 | 조정 이유 |
|---|---|---|
| 나일의 분노 | 피해7×5 유지, 전체 독1→2 | 히트마다+1로 증폭하지 않고 보조 효과를 강화 |

실제 즉시 효과 **1728쌍 중 이상치4쌍**은 모두 사막 기마의3드로우 상태(0/1강,1/3인팀)다. 옛 기준 환산값7.5/8.1에 대해 후보는9/12다. 인게임 후보는 정수이며 이 소수는 분석용 비교값이다. 후보가 강화될수록 원본 대비 차이가 커지므로 **밸런스 합격으로 처리하지 않는다**. 조건부 기마 돌격의 강화/조건 피해, 방어·매혹 소비 계수, 사기 시너지 등 확인된 단위 오류는 수정했다.

손패 선택 미완료 **8쌍**은 자동 합격이 아닌 coverage gap이다. 권능의 이후 턴 성능도 별도 검증이 필요하다. 미분류 숫자 필드0개, 한국어 후보 설명에서 숫자 소수 표시0개를 확인했다. 모든216개 카드의 후보 강화 데이터가 달라지는 것을 검증했지만, 이는 실제 전투에서 항상 유용한 강화라는 증명은 아니다.

최종 로컬 보고서: `/tmp/STSL-small-number-comparison-final.json`. SHA256 `e9ba5a4d10d67a8f53de5ef6d8bee7db8d769337f67efde4f39e397e1939f6a5`. 전체 로그: `/tmp/STSL-small-number-regression-verified.log`. 임시 파일은 영구 보관을 보장하지 않으며 위 실행기로 재생성할 수 있다. 보고서에216개 카드의 이름/비용/효과/규칙/설명과 전체 비교 행이 포함된다.

후보 쌍 생성기는0/1강 평가용이다. 위 개별 튜닝을 일반 GameManager 강화 흐름에 아직 연결하지 않았다. 카드 데이터·몬스터·세이브 전체 전환과 캠페인 비교 전에는 기본 게임에 활성화하지 않는다. 커밋·푸시는 하지 않았다.
